四个功能一次做完,除取餐码外均在真实环境验证。

1. 多门店比价(新增 compare 命令与 compare.py)
   - 同一配送地址下对每家可配送门店各跑一遍完整链路,按**实付金额**升序排序
   - 真实结果:无锡某地址 3 家门店 -> 永乐路 285.50 / 云蝠 293.00 / 五爱路 295.00,
     最省比最贵省 ¥9.50
   - 关键设计:单店失败不影响整体(歇业/缺 beCode/空菜单都单独标注原因),
     不污染调用方 requirements,可导出 Markdown/JSON
   - 从 Session 拆出 load_catalog_for / plan_for,比价复用同一段求解逻辑而不复制

2. 真实门店快照再生(重写 tools/regen_fixtures.py)
   - 支持多门店、多场景;真实抓取了无锡 3 家门店的麦乐送快照(每家 120+ 编码取价成功)
   - **价格与券快照文件名带场景后缀**(.<orderType>.<beType>.json):
     同一门店到店价与外送价不同,不带后缀会互相覆盖,离线演示会给出错误金额
   - 新增 delivery-query-stores.<addressId>.json 快照,让离线模式也能解析
     门店名与 beCode(此前离线外送场景会因为缺 beCode 直接报错)
   - 客户端快照查找同步支持场景后缀优先

3. 支付卡片多格式(--share-format 与扩展名自动推断)
   - 支持 text / md / json;.md 输出表格 + 可点击支付链接,
     .json 输出可被程序消费的字段(订单号/支付链接/截止时间/取餐码)
   - 未知格式回落到纯文本,不抛异常

4. 取餐码提醒
   - 支付卡片与 JSON 输出带 pickupCode;新增 pickup_reminder()
   - 取餐码只有进入「配餐中」后才有值,因此**没有就不显示、不编造**
   - order status 在已支付状态下额外展示取餐码与取餐柜码
